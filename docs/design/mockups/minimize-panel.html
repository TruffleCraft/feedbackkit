Minimize the panel and keep the report

Issue #170. Sam is on example.org and starts a report on the orders page. To show the problem, Sam needs a second page. Today the panel is modal: the backdrop covers the page and on a phone the sheet fills the screen. Below are three ways to shrink the panel to something small, keep the draft while Sam moves on, and add a screenshot of the next page. A was chosen. Further down: the list of reports sent in this session.

What exists today

  • The panel sits on .fk-backdrop and locks page scroll. Below 600 px it is a full-screen sheet.
  • Close from the form already keeps the draft in memory, so a single-page app gets it back on the next open. A page load loses it. The widget writes nothing to browser storage.
  • Screenshots stay Blobs until Send. Manual attachments upload when picked.
  • feedbackkit:open and feedbackkit:close (#169) mark start and end of a report. QUICKSTART already promises that minimizing will not fire close.
  • The widget is 23,436 bytes gzipped against a budget of 23,552. 116 bytes are left.

What support widgets do

  • Intercom: hide closes the panel and leaves the launcher. Only shutdown clears data. A cookie keeps conversations for a week.
  • Zendesk messaging: close collapses the window, hide removes the launcher, reset clears state. It uses cookies plus local and session storage.
  • Help Scout Beacon: close keeps the contact form. reset clears its fields and attachments.
  • Crisp: a cookie on the domain restores the history, so a page view does not start a new conversation.

The pattern taken over

Minimizing and ending are two separate acts. Minimizing never loses anything. Ending (send, discard) is the only thing that clears the draft and fires feedbackkit:close.

Unlike a chat, there is no conversation on the server before Send. The draft lives in the tab, so sessionStorage is used instead of a cookie: it stays with the tab and is gone when the tab closes.

The same in every variant

A minimize button sits left of close. Minimized, the backdrop and the scroll lock go away and the host page works as usual. The restored panel shows each screenshot with the path of the page it came from.

Byte counts are not measured. All three need more than the 116 bytes that are left, so the budget question comes before the build.

Recommendation

Build A. One tap on the pill takes a screenshot of the page Sam is on, so several pages fit in one report without opening the panel each time. The pill shows that a draft is waiting and how much is in it, and it sits where the trigger sits today, above the tab bar (--fk-trigger-bottom). Its storage follows the issue: text, id and upload keys in sessionStorage, screenshots uploaded on capture through the same call manual attachments use. The panel shows no type picker: the gateway picks the type (#172).

Fall back to C if the budget cannot grow by much. It covers single-page apps and phones but loses the draft on a full page load.

Sent in this session

After Send, Sam sees how the gateway understood the report, as today. New: every sent report goes into a list in the tab, so Sam can look back at what went out, with the ticket link when the project allows it (issueLink).

Kept per entry

  • The gateway's summary and the type it picked
  • Time and page path
  • The report id
  • The ticket link only with issueLink: true. Otherwise a short reference taken from the report id.

Not shown

  • No live status: GitHub owns it, and the widget asks nothing after Send.
  • A report still being delivered keeps the state it had at Send.
  • The full issue text, its fields and the console log stay out.

Where it lives

  • sessionStorage, next to the draft. It is gone when the tab closes, and a new tab starts empty.
  • Not localStorage: on a shared computer the next person would read the summaries.
  • The trigger shows no count, so the list never looks like unread messages.

Decided

  1. Variant: A, the pill.
  2. Escape and ×: Escape minimizes. × with unsent text asks "Discard this report?"
  3. Hidden content while minimized: content a page hides on feedbackkit:open stays hidden until the report ends, as QUICKSTART promises, and there are no new events. The camera on the pill can capture at any time, so hidden content has to stay hidden while minimized.
  4. Leftovers: uploaded screenshots that never got a report are deleted after 24 hours. A draft lasts until the tab closes.
  5. Bundle budget: it goes up. The build PR measures by how much.
  6. Sent list: as shown above, per tab.
  7. Type picker: gone by default, the gateway picks the type (#172). New projects through a guided chat later (#173).
